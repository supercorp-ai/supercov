# Rust coverage v1 requirement traceability

This table distinguishes a frozen semantic requirement from implementation
evidence. A frozen row is not complete until every listed gate is green. The
private frontend must fail closed for every open row.

| ID | Requirement | Current executable evidence | Promotion gate |
|---|---|---|---|
| RCV-IDENTITY-1 | Stable authored-source identity and generic aggregation | Frozen source-identity-v1 tuple plus compiler-manifest candidate; exact manifests survive two clean target directories, repeated declarative expansions aggregate, distinct proc-macro invocations remain distinct and generated IDs contain no ephemeral path | Cross-crate generic/trait/derive corpus and collision/fingerprint matrix |
| RCV-POINT-1 | Statements and function entries | Compiler candidate emits stable function/statement points across authored, repeated declarative, proc-macro and generated source; selected function probes carry their manifest-derived ordinal. Compiler `while`/`for` lowering scaffolding is explicitly excluded while the enclosing authored construct retains its own obligations | Remaining executable-point semantics, complete probes and independent rustc differential corpus |
| RCV-MCDC-1 | Source-ordered ternary masking MC/DC | Expanded HIR identifies `if`, `if let`, let-chain, `while`, `while let`, match-guard and assertion atoms; rustc branch regions and structural markers are translated into Supercov-owned per-evaluation MIR frames. Goldens prove `&&`, `||`, mixed `(a || b) && c`, nested value-producing decisions, nested-pattern and let-chain conditions, compound `while`, `while let` chains, two-atom authored and synthetic match guards, and `assert!`/`debug_assert!` conditions, plus declarative-macro, proc-macro and build-generated ternary vectors with exact outcomes and concurrent libtest contexts. Condition panic and process kill never publish a false complete vector | Remaining decision kinds, full contract goldens and independent LLVM cross-check |
| RCV-SEMANTICS-1 | Preserve values, moves, borrows, drops, panic and ordering | Compiler companion injects the production-shape mmap runtime plus real MIR calls; baseline/instrumented values, errors, caught panic, drops and output match while function ordinals, authored decision vectors and loop alternatives arrive. Hidden external-macro and compiler-desugaring control flow is excluded from the authored denominator. The exact-version compiler switch prevents LLVM profiler injection, and the linked-binary/profile-output gate proves the product path remains Supercov-owned | Property/differential corpus across supported toolchains |
| RCV-BRANCH-1 | Every frozen branch alternative | Candidate manifests use only frozen branch kinds for the implemented slice. `if`, `if let`, let-chain, `while` and `while let` outcomes are exact. `while` and `for` invocations emit separate zero-iteration/entered alternatives with one first-commit frame. `for` probes bind before optimization to rustc's exact desugared `Option::None`/`Some` switch. Reachable match arms use a persisted selection group: one raw selected-arm commit derives the selected alternative and every sibling's not-selected alternative offline. Goldens distinguish guarded, nested, identical, empty, local declarative-macro and collapsed-span proc-macro arms, including synthetic matches nested in bodies, scrutinees and guards; a guard panic leaves an incomplete frame and no false selection. Irrefutable one-arm and compiler-unreachable arms create no impossible branches. `let else` emits exact matched/else first-commit alternatives for simple and nested patterns, multiple sequential statements and collapsed proc-macro source; synthetic endpoint markers survive borrow checking exactly once and are removed before runtime instrumentation. `?` emits exact continued/early-return alternatives for `Result`, `Option`, sequential and nested operators, and collapsed proc-macro source. Its frame starts only after `Try::branch` returns, so an operand panic commits no false alternative. Authored and collapsed proc-macro `assert!`, `assert_eq!`, `assert_ne!` and debug variants emit exact passed/failed alternatives; `assert_ne!` preserves its inverted compiler comparison, operands evaluate once in source order, a condition panic emits no false failure, and failure is committed before a panicking message argument | assertion-phase attribution, derive/external expansion corpus, generic evidence-v3 expansion and exhaustive contract vectors |
| RCV-EXPANSION-1 | Declarative macro expansions | Compiler candidate aggregates function, statement, decision and branch identities for two expansions of the same authored macro token ranges; the shared decision ID receives distinct exact runtime vectors from both generated functions. A local declarative-macro-generated match preserves two exact arm selections | Nested/external macro corpus and complete point/branch probes |
| RCV-EXPANSION-2 | Proc/derive expansions | Compiler candidate binds collapsed proc function/statement/decision/branch output to stable callsite + complete expansion chain + owner-local ordinal, separates repeated invocations and emits exact decision vectors for both. Built-MIR semantic markers preserve unguarded, guarded and recursively nested proc-macro match groups after their spans collapse. Frozen HIR parent/site identity plus CFG reachability produces one fail-closed assignment for body-, scrutinee- and guard-nested groups; condition markers independently preserve exact synthetic guard vectors. Every marker survives borrow checking exactly once and is removed before runtime calls | Attribute/derive/external proc corpus and complete point/branch probes |
| RCV-GENERATED-1 | Build-script and included generated source | Compiler candidate keys owned `OUT_DIR` function/statement/decision/branch source by project-relative package root + out-relative path, is byte-identical across target directories and emits the generated decision's exact runtime vector | Package/build-script fingerprints, complete probes and crash/symlink corpus |
| RCV-CONST-1 | Const/static/const-fn execution | Exact-version companion inserts in-memory CTFE block and split-edge markers; both const-fn paths are observed with identical values/output | Full const/static/inline-const/const-generic manifest, semantics, concurrency, crash and performance corpus |
| RCV-DOCTEST-1 | Doctest extraction and attribution | Scoped exact-rustdoc launcher observes standalone/merged sources; hidden lines and merged `__doctest_N` path/line identities are mapped without enabling unstable user code | Runtime probes, exact per-doctest attempt transport, wrapper composition and full doctest corpus |
| RCV-TRANSPORT-1 | Bounded, authenticated, crash-safe observation publication | Frozen `rust-probe-transport-v1`; thread/process concurrency, descriptor/payload exhaustion, malformed token/context/header/descriptor/checksum, symlink, incomplete record and killed-writer tests. Decision and first-commit branch frames preserve their start context across thread migration; killed unfinished frames remain explicit incomplete records | Dynamic exact-context propagation, Linux target matrix and Windows implementation before those targets are claimed |
| RCV-ATTRIBUTION-1 | Exact run/worker/test/retry/phase identity | Transport records a context ID per observation; rustc marker-derived entry/normal-exit/unwind instrumentation separates concurrent ordinary, attribute-macro and expected-panic libtests. Assertion phases derive deterministic child contexts from the active test/assertion context plus stable assertion decision ID. Goldens prove argument evaluation, post-assertion restoration, nested assertion restoration and unwind behavior. The production engine now selects the exact companion through Cargo, preflights every libtest context, launches one authenticated mmap/process per attempt, validates the real compiler manifest and transport, projects repeated/nested assertion contexts into distinct evidence-v3 phases, and keeps context-zero observations in separate background results. A full Cargo fixture reaches the shared frontend validator and analyzer with exact test/worker/retry/phase identities and zero dropped evidence | Exact Cargo/libtest selection and retry capture; subprocess, crash and late-work corpus |
| RCV-ARCHIVE-1 | Strict evidence v3 publication and query | Evidence/archive/run-store tests plus a compiler-run isolated-workspace, compressed-archive, atomic-publication and normal-query roundtrip. The immutable query index now has typed source-discovery and compiler-owned scope shapes instead of requiring JavaScript fields from every language | Full compiler-run lifecycle crash, ENOSPC and concurrent-run matrix |
| RCV-ORACLE-1 | No external product measurement | Contract assertion | rustc/LLVM oracle-only CI with product-dependency audit |
| RCV-PERF-1 | Warm and cold runtime at most 1.10x | Benchmark harness exists | Stable median gate on representative Rust corpus |

The open gates are intentional release blockers, not deferred semantics.
